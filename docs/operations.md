# Эксплуатация

## Первый запуск

1. Выполните `./scripts/init-env.sh` из корня проекта. Скрипт не перезаписывает существующий `.env`.
2. Откройте `.env`, сохраните `OPERATOR_PASSWORD` в менеджере паролей.
3. Запустите `docker compose up --build -d`.
4. Проверьте `docker compose ps` и `docker compose logs api mediamtx casparcg`.
5. Откройте http://localhost:8088, войдите и создайте канал.
6. Выберите резервный источник в Preview и выполните CUT. Дождитесь появления HLS-видео; задержка в несколько секунд нормальна.

CasparCG собирается из официального Ubuntu PPA, используется Xvfb и программный OpenGL. Этот вариант требует проверки драйверов/CEF на вашем хосте. На серьёзном вещательном сервере предпочтителен отдельный CasparCG с проверенной сборкой и GPU. Укажите `Caspar__Host`, общий media-каталог, шаблон `graphics/lumiere.html` и восемь каналов согласно конфигурации.

В контейнере API есть FFmpeg/FFprobe. В media-volume нужны права записи пользователя `app`; у CasparCG чтение. Резервируйте PostgreSQL, media и keys одновременно. Без volume keys невозможно расшифровать сохранённые ключи S3 и старые cookies.

## Пароль

`OPERATOR_PASSWORD` используется только для первичного создания учётной записи. В панели «Настройки» можно установить новый пароль от 12 до 128 символов. Хранится хеш ASP.NET Identity, а не исходный пароль. Смена повышает версию безопасности и аннулирует существующие API-сеансы. Уже открытое SignalR-соединение может оставаться до переподключения, но команд управления через hub нет.

Изменение `.env` после создания БД не сбрасывает пароль. Аварийный сброс пока выполняется администратором отдельно; не удаляйте рабочую БД ради сброса. Не передавайте пароль в URL.

## Внешний доступ

По умолчанию HTTP доступен только на localhost. Для публикации:

- Настройте HTTPS непосредственно на gateway и укажите `PUBLIC_ORIGIN=https://ваш-домен`.
- Установите нужный `HTTP_BIND` и ограничьте доступ к панели при необходимости сетевым экраном/VPN.
- Не открывайте наружу PostgreSQL, API, AMCP 5250, HLS 8888 и Control API 9997 MediaMTX.
- Если перед gateway добавляется ещё один proxy/CDN, настройте реальный IP на nginx с доверием только к конкретным адресам этого proxy. Затем передавайте восстановленный `$remote_addr` в API. Иначе GeoIP увидит IP прокси.
- При завершении TLS на внешнем прокси также восстановите доверенный `$scheme`/`X-Forwarded-Proto`; иначе защищённая cookie не будет работать как ожидается. Не доверяйте внешнему `X-Forwarded-For` без ограничений.
- Не кешируйте `/hls/` публично. Проверяйте доступ к сегментам напрямую.

RTMP 1935 открыт для OBS; публикация требует случайный ключ канала. Используйте TLS-транспорт или защищённый туннель, если сеть недоверенная. RTMP без TLS передаёт данные и ключи без шифрования.

## OBS

В «IPTV и подключения» скопируйте сервер и ключ. В OBS выберите настраиваемый сервис, H.264/AAC, 1080p25, ключевой кадр каждые 2 секунды. Запустите трансляцию, выберите OBS в Preview и выполните TAKE. Каждый канал получает независимый ключ.

Для прямого источника CasparCG читает RTMP с внутренними engine-учётными данными. Их UI не получает. Чтение сырых потоков MediaMTX без этих данных запрещено.

## Видео и S3

Локально: в «Медиатеке» загрузите MP4/MOV/MKV/WebM до 2 ГБ и не более 24 часов. Проверка не означает полного декодирования/лечения повреждённого файла. Для точных переходов и seek нормализуйте материал в 1080p25, H.264/AAC.

S3: сохраните HTTPS endpoint без пути, bucket, регион подписи, Access Key и Secret Key. Ключу достаточно `s3:ListBucket` на bucket и `s3:GetObject` на выбранный префикс. Приложение не записывает и не удаляет объекты в S3.

Нажмите «Показать файлы», при необходимости задайте префикс. Укажите реальную длительность ролика и выберите «Подключить»: это сетевой источник без записи на диск. В Program CasparCG скачивает только необходимые данные по мере чтения. Перемотка и стабильность зависят от хранилища. MP4 должен иметь индекс в начале (`faststart`). Подписанный URL не показывается в UI; он передаётся медиадвижку.

«Импорт» скачивает полную локальную копию с проверкой FFprobe; состояние видно в очереди. Лимит 20 активных заданий на канал, один импорт одновременно, предел 2 ГБ на объект. Отдельных quota по диску и автоматического удаления старого контента пока нет; контролируйте свободное место.

S3-провайдер должен поддерживать выбранный тип адресации и SigV4. Реальные учётные данные стороннего провайдера в среде разработки не использовались; первым делом проверьте листинг, Range, запуск и seek одного короткого ролика. Нельзя использовать localhost/внутренний MinIO в этом профиле.

## Ограничения по региону

Поместите базу MaxMind в `geoip/`, проверьте лицензию и установите `GEOIP_DATABASE`. Перезапустите API после обновления файла. Укажите ISO-коды стран или коды подразделений из City. Без базы включение заблокировано. Для неизвестных IP оставьте включённой заставку.

После включения подождите несколько секунд, пока FFmpeg опубликует заставку. Можно загрузить PNG/JPEG до 8 МБ; изображение приводится к 1920 × 1080. Для проверки используйте реальные выходы из разрешённого и запрещённого региона, а также прямую ссылку на сегмент. Изменения правил во время просмотра могут потребовать перезапуска плеера.

## Диагностика

| Признак | Что проверить |
|---|---|
| 401 в панели | Пароль, cookie, HTTPS, версия сеанса |
| 403 при сохранении | Соответствие `PUBLIC_ORIGIN` адресу браузера |
| 409 при TAKE | Кто-то изменил состояние; обновите данные |
| 503 при переключении | AMCP, доступность CasparCG, номера каналов |
| Команда принята, изображения нет | Логи CasparCG, кодек/URL, публикация MediaMTX, HLS |
| Заставка не запускается | FFmpeg, файл, права media, пароль engine |
| GeoIP не подключён | Путь `.mmdb`, права, формат базы, перезапуск API |
| S3 301/403 | Регион подписи, endpoint, bucket и права ключа |
| Неверная позиция после restart | FPS материала и поддержка seek/Range |

API `/health/live` проверяет процесс, `/health/ready` — доступность базы. Эти endpoints не означают исправность видеотракта.

## Локальная разработка

Для разработки доступен SQLite (`Database__Provider=Sqlite`, `ConnectionStrings__Database=Data Source=...`), только для тестов/одного разработчика. Production использует PostgreSQL и миграции.

Перед `dotnet run --project src/Broadcast.Api` задайте секреты длиной не менее 24 символов, `PublicOrigin=http://localhost:3000`, `ASPNETCORE_URLS=http://localhost:5080`, `Media__Directory` и путь стандартной заставки. В `src/broadcast-web` выполните `npm ci && npm run dev`. Next.js проксирует API/HLS на порт 5080; в Docker маршрутизацию выполняет nginx.

`Worker__Disabled=true` отключает фоновые медиапроцессы для проверки UI/API. Команды Preview/TAKE всё равно требуют настоящий CasparCG и не имитируют эфир.

## Российские провайдеры S3

В форме есть готовые профили. Endpoint, регион и вид адресации остаются редактируемыми; параметры должны совпадать с вашим bucket.

| Профиль | Endpoint | Регион подписи | По умолчанию |
|---|---|---|---|
| Яндекс Object Storage | `https://storage.yandexcloud.net` | `ru-central1` | Path-style |
| Selectel Санкт-Петербург | `https://s3.ru-1.storage.selcloud.ru` | `ru-1` | Virtual-hosted |
| Selectel Санкт-Петербург ru-3 | `https://s3.ru-3.storage.selcloud.ru` | `ru-3` | Virtual-hosted |
| Selectel Москва | `https://s3.ru-7.storage.selcloud.ru` | `ru-7` | Virtual-hosted |
| VK Cloud Москва | `https://hb.ru-msk.vkcloud-storage.ru` | `ru-msk` | Path-style |

Выбирайте вид адресации, который включён у контейнера; особенно это важно для Selectel. Для других российских провайдеров используйте «Свой S3-совместимый провайдер». Кириллица, пробелы и вложенные папки в ключах объектов кодируются UTF-8 при подписи. Ключи с сегментами `.`/`..` намеренно отклоняются, чтобы HTTP-клиент не нормализовал путь к другому объекту.

Профили сверены с документацией; успешное воспроизведение с реальными ключами каждого провайдера требует отдельной приёмки.
